Supabase Auth deployment checklist

1. Run the entire `supabase/gmail_tokens.sql` file in Supabase SQL Editor. This creates the service-only credential table referencing `auth.users`. Do not run the old custom-user migrations for this change. Existing custom accounts do not carry over; users must register again or use Google.
2. Set Vercel production variables from `.env.example`: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_KEY`, `APP_URL=https://certify-zip.vercel.app`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`. Remove `JWT_SECRET` and the old `SUPABASE_URL` requirement. The optional `GOOGLE_REDIRECT_URI` must be `https://certify-zip.vercel.app/api/auth/gmail/callback`. Redeploy after setting public variables: Next.js embeds them at build time, even though clients are created lazily.
3. In Supabase Authentication, enable Email and Google providers. Configure Google credentials in Supabase. Set Site URL to `https://certify-zip.vercel.app`; allow `https://certify-zip.vercel.app/auth/callback` and `https://certify-zip.vercel.app/auth/callback?next=reset-password`. Configure email confirmation and SMTP delivery as needed. Google login uses Supabase's default identity scopes only.
4. In Google Cloud, authorize the Supabase Google callback shown in its provider configuration (`https://YOUR_PROJECT.supabase.co/auth/v1/callback`). Separately authorize `https://certify-zip.vercel.app/api/auth/gmail/callback` for the Gmail client. Enable Gmail API and Sheets API. Configure consent screen/test users and Gmail send plus Sheets readonly permissions. Gmail connect keeps Sheets access to preserve the existing import feature.
5. Keep the existing `certificates` storage bucket and upload settings. No storage schema or upload payload changes are required.
6. Register a new email account, confirm its email, then sign in. Verify wrong password, duplicate registration, weak password, password reset, and a stalled connection: buttons become usable after 30 seconds. Check login layout remains unchanged.
7. Continue with Google: verify the account picker, return to `/`, persistent login after reload, and no Gmail permission request during login. Cancel sign-in and verify a readable error. Sign out, then confirm `/api/auth/me` returns 401 JSON and POST `/api/upload-url`, `/api/send`, `/api/sheets` require authentication.
8. Connect Gmail. Skip the Gmail checkbox and verify “Tick the Gmail permission box” and Reconnect; sending must return 401 `RECONNECT_GMAIL`. Reconnect and grant permission; verify the correct sender email appears.
9. Upload and send a certificate. Verify its full PDF attachment opens intact, including a large PDF. In SQL Editor, set this test user's `google_token_expiry` to 0 and verify sending refreshes it. Revoke Google consent and verify a reconnect response.
10. Use two separate browser profiles for two Supabase users and two Gmail accounts. Verify each sends from its own Gmail account; an unconnected user cannot use the other's credentials. Verify anon/authenticated API clients cannot read or write `gmail_tokens`.
11. Verify Excel import, Google Sheets import, template editing, generation, preview, send progress, and failed-row correction retain their behavior. OAuth and email delivery checks require the configured live services; local mocked tests cannot establish them.
